## MODIFIED Requirements

### Requirement: Незмінність типу значення поля
Система SHALL забороняти змінювати тип значення поля після його створення, незалежно від наявності збережених значень, і SHALL дозволяти змінювати його назву, вагу та налаштування. Збереження поля з тим самим типом SHALL не вважатися зміною типу.

#### Scenario: Спроба змінити тип
- **WHEN** змінюється тип поля, що має збережені значення
- **THEN** зміну відхилено, наявні значення не змінюються

#### Scenario: Спроба змінити тип поля без значень
- **WHEN** змінюється тип поля, для якого немає збережених значень
- **THEN** зміну відхилено, тип поля лишається попереднім

#### Scenario: Зміна інших властивостей
- **WHEN** змінюються назва, вага або налаштування поля, а тип лишається тим самим
- **THEN** зміни збережено

### Requirement: Каскадне видалення конфігурації
Система SHALL забороняти видаляти поле, що має збережені значення, для будь-якого шляху видалення (адмінка, код, імпорт), залишаючи поле й значення без змін; поле без значень SHALL видалятися. При видаленні типу контенту система SHALL видаляти його поля, записи та їхні значення.

#### Scenario: Видалення поля
- **WHEN** видаляється не системне поле без збережених значень
- **THEN** поле видалено, значення інших полів збережено

#### Scenario: Видалення поля зі значеннями
- **WHEN** видаляється поле, для якого існують збережені значення (хоча б в одному записі чи мові)
- **THEN** видалення відхилено, поле й усі його значення лишаються без змін

#### Scenario: Видалення типу контенту
- **WHEN** видаляється тип контенту, чиї поля мають значення
- **THEN** видалено його поля, записи та їхні значення
