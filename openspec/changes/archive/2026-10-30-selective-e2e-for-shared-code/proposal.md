# Proposal

## Why

Правило «повний `npm run test:e2e` після будь-якої правки спільного коду» надто грубе: зміна `DataTable` потребує лише спеків, що його використовують (зараз 5 із 9), а не `smoke` чи `admin-i18n`. Повний набір працює в один потік і росте разом із кількістю спеків, тож розробка гальмується без користі для страховки від регресій.

## What Changes

- Для змін у **спільному компоненті** (наприклад, `DataTable`) запускаються лише залежні спеки. Їх визначають за використанням компонента в застосунку й за новою колонкою «Спільний код → спеки» в таблиці `docs/e2e-testing.md`.
- **Повний прогін** `npm run test:e2e` лишається лише для змін, що зачіпають усі спеки: `playwright.config.js`, `e2e/global-setup.js`, автентифікація, оболонка/sidebar.
- У кінці завдання/правки звіт **завжди називає запущені й пропущені спеки та причину пропуску**. Перед запуском про вибір не питаємо; питаємо лише коли межу впливу неможливо визначити з коду або набір вийшов майже повним.
- Новий спек або новий споживач спільного компонента оновлює колонку «Спільний код → спеки» (поряд із наявним рядком «область → спек»).
- Правило закріплюється в `CLAUDE.md` (розділ Playwright), `openspec/config.yaml` (`rules.tasks`) і `docs/e2e-testing.md` (розділ «Коли запускати e2e»).

### Modified Capabilities

## Impact

- Правила: `CLAUDE.md`, `openspec/config.yaml`. Коду застосунку й тестів це не змінює.
- Docs: оновити `docs/e2e-testing.md` (розділ «Коли запускати e2e», нова таблиця «Спільний код → спеки»); `docs/README.md` — без змін, назва файла не змінюється.
- Не входить: паралелізація (`workers`), CI, `--only-changed` (не бачить коду застосунку).
