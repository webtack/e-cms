# Design

## Context

Див. `proposal.md` (Why). Поточний стан, який визначає підхід:

- Оригінали лежать у корені диска профілю `image` (`public`) як `{uuid}.{ext}`; `public/storage` — симлінк на `storage/app/public`, URL диска — `APP_URL/storage`. `FileStorage::url()`/`urlForValue()` будують URL з диска.
- Шаблони теми отримують **готовий URL** зображення (`present()` типу `image`, `$meta['image']`, `$logoUrl`), а не `File`; отже хелпер має працювати від URL, без БД.
- `ImageResizer::resize($path, $mime, $maxW, $maxH)` уже масштабує пропорційно без збільшення, застосовує EXIF, пропускає анімовані GIF/WebP й повертає `null`, коли зміни не потрібні; для стилів його розрахунок розміру й визначення анімації використовуються повторно, а композицію з розмитим тлом додає новий метод.
- Доступу до конфігурації вебсервера на хостингу немає. Але і `public/.htaccess` (Apache), і `docker/nginx/default.conf` (`try_files $uri … /index.php`) стандартно віддають запит неіснуючого файла front controller — це єдина вимога до середовища.
- Опис файлового сховища: `docs/file-storage.md`; медіатеки: `docs/media-library.md`; шаблонів теми: `docs/theme-templates.md`. Новий документ — `docs/image-styles.md`.

## Goals / Non-Goals

**Goals:**
- Хелпер без I/O, що повертає адресу стилю; пресет `thumb` готовий одразу після завантаження, решта створюється на запит; працює без правил вебсервера.
- Стиль із двома сторонами завжди дає зображення точно заданого розміру, без обрізання оригіналу.
- Довільні розміри без можливості для стороннього навантажити сервер розмірами.

**Non-Goals:**
- Обрізання, `srcset`, зміна формату, водяні знаки, черга, масове генерування наперед.
- Переведення шаблонів `default` на хелпер; інші стилі в адмінці крім `thumb`; деталі файла в медіатеці й скрін YouTube.
- Стилі для файлів поза профілем `image` (інші диски).

## Decisions

**1. Адреса й файл: `{диск}/styles/{стиль}/{uuid}.{ext}`.** Каталог за вимогою власника; `uuid` той самий, що в оригіналу, розширення — за форматом стилю (див. рішення про формат), тож хелпер вставляє сегмент перед іменем файла й міняє розширення детерміновано, без I/O. Альтернатива — суфікс у імені (`{uuid}--thumb.jpg`) відкинута: вимога каталогів `styles/{name}`, і видалення/очищення стилю = видалення каталогу.

**2. `thumb` при завантаженні, решта ліниво через Laravel-маршрут.** Пресет з ознакою `upload` у конфігурації `FileStorage::store()` створює одразу після запису оригіналу (в тому ж запиті), за тим самим алгоритмом, що й ліниво, тож адмінка завжди має готову мініатюру. Збій створення (виняток) перехоплюється й логується, завантаження не відхиляється: пресет створить ліниво маршрут. Для всього іншого — довільних розмірів, пресетів без `upload`, файлів, завантажених до зміни, та після `image-styles:flush` — працює ліниве створення нижче.

**Ліниво через Laravel-маршрут `GET {шлях URL диска}/styles/{style}/{file}`.** Коли файл уже лежить на диску, вебсервер віддає його статично й до PHP запит не доходить; коли немає — стандартний fallback (`.htaccess`, `try_files`) віддає запит Laravel. Шлях маршруту береться з URL диска профілю `image` (`parse_url(Storage::disk(...)->url('styles'), PHP_URL_PATH)`), а не вшивається. Контролер: валідує `file` за `FileValue::PATTERN`, розбирає й перевіряє стиль і підпис, знаходить оригінал за `uuid` (перебирає дозволені розширення профілю; розширення запитаного файла має збігатися з `ImageStyles::extension()` знайденого оригіналу, інакше 404), викликає `ImageResizer`, записує результат (атомарно: запис у тимчасове ім'я й перейменування, щоб паралельні запити не віддали недописаний файл), віддає відповідь. Коли обробка не потрібна (анімація), у файл стилю копіюється вміст оригіналу: наступні запити статичні, а хелперові не треба знати, чи потрібна обробка. Помилка декодування → 404 і нічого не записується. Альтернатива — генерація при завантаженні: потребує міграції старих файлів і хелпер не знав би, чи файл існує (потрібен запит до БД чи диска).

**3. Розбір стилю — `App\Files\ImageStyles`.** Стиль `thumb` шукається в `config('files.styles.presets')` (`['thumb' => ['width' => 200, 'height' => 200]]`, значення з `.env`), інакше матчиться `^(\d+)?x(\d+)?$` (лише латинська `x`, без урахування регістру; велика нормалізується до малої), хоча б одна сторона обов'язкова, кожна в межах `1..files.styles.max_dimension` (4096). Нормалізована назва `{w}x{h}`, `{w}x`, `x{h}` — ім'я каталогу. Назва пресету має не збігатися з цим форматом (перевіряється при зчитуванні конфігурації; порушення — виняток).

**Композиція стилю з двома сторонами (`ImageResizer::fit()`).** `scale = min(W/w, H/h)` **без обмеження 1**: менший оригінал збільшується (стилі відрізняються від завантаження, яке не збільшує); `fg` = оригінал, масштабований цим коефіцієнтом, тож він завжди торкається полотна принаймні однією стороною. Якщо `fg` рівно W×H — це звичайний resize. Інакше будується полотно W×H: тло — той самий оригінал, масштабований «на покриття» (cover, зайве обрізається по центру), розмитий (`blur`, сила `files.styles.blur`, за замовчуванням 30; тло будується зі зменшеної копії, а потім розтягується, бо так розмиття дешевше за повнорозмірне), поверх по центру `fg`. Якщо зображення має прозорі пікселі, тла немає: полотно прозоре, `fg` стоїть по центру. Наявність прозорості визначається за фактичними пікселями (альфа-канал використаний), а не за форматом файла: PNG без прозорості дістає тло. Для перевірки використовується нативний `Imagick` через драйвер Intervention. Стиль з однією стороною — `scale` за цією стороною (з дозволеним збільшенням), без тла. Альтернативи: однотонний фон, crop (оригінал має лишатися видимим цілим), розмите тло під прозорими ділянками (дає брудне «гало» навколо логотипів і PNG-ілюстрацій).

**Формат файла стилю (`files.styles.format`, `.env` `FILES_STYLE_FORMAT`).** `webp` (за замовчуванням) або `original`. У режимі `webp` JPEG, PNG і WebP-оригінали віддаються як WebP із якістю `files.image.quality.webp` (WebP менший за JPEG, підтримує прозорість, читається всіма сучасними браузерами), розширення файла стилю — `webp`. GIF-оригінали лишаються GIF в обох режимах: хелпер без I/O не знає, чи GIF анімований, а анімацію не можна перетворити, тож розширення має бути передбачуваним. Анімований WebP-оригінал копіюється як є під ім'ям `{uuid}.webp`. У режимі `original` розширення збігається з оригіналом. Невідоме значення налаштування — виняток при зчитуванні конфігурації. Сигнатура: `ImageStyles::extension(string $originalExt): string`.

**4. Підпис довільних розмірів — `itok` = перші 16 hex-символів `hash_hmac('sha256', "{style}|{file}", APP_KEY)`.** Без нього будь-хто міг би запитувати тисячі розмірів і заповнювати диск/CPU. Хелпер знає ключ і додає токен; пресети не підписуються, бо їх скінченна кількість. Токен лежить у query: вебсервер ігнорує query для статичного файла, а Laravel перевіряє `hash_equals`. Токен прив'язаний до стилю й імені файла, але не до користувача й не має терміну дії (мета — обмежити перелік розмірів, а не сховати файл). Альтернативи: підписаний URL Laravel (термін, довгий підпис, залежить від повного URL з хостом) — не підходить: адреса має бути стабільною й кешованою; білий список розмірів — суперечить вимозі довільних значень.

**5. Хелпер `image_style(?string $url, string $style): ?string`.** Глобальна функція, що підключається через `autoload.files` у `composer.json` (файл `app/helpers.php`), і делегує `ImageStyles::url()`. Алгоритм без I/O: `null`/порожнє → `null`; якщо ім'я файла (`basename` шляху без query) не відповідає `FileValue::PATTERN`, або стиль некоректний — повернути вхід без змін; значення `{uuid}.{ext}` без `/` перетворюється на URL диска профілю через `FileStorage::urlForValue`; інакше вставити `styles/{стиль}/` перед іменем файла збережений початок URL (схема, хост, каталог), замінити розширення на `ImageStyles::extension()` і додати `?itok=` для довільного розміру (підпис рахується від імені файла стилю, з новим розширенням). Для оригіналу, що лежить не в сховищі профілю `image` (інший каталог), адреса матиме неправильний каталог — це дає 404 від маршруту: прийнятно, бо поле `image` завжди пише в диск профілю `image`.

**6. Видалення.** `FileStorage::delete()` після видалення оригіналу викликає `ImageStyles::forget($disk, $path)`: для кожного каталогу з `Storage::disk($disk)->directories('styles')` видаляє всі файли `{каталог}/{uuid}.*` (розширення стилю може відрізнятися від оригінального); відсутнє — не помилка. Порядок «рядок спершу (FK може відмовити), диск потім» зберігається, тож відхилене видалення стилів не чіпає.

**7. Команда `image-styles:flush {style?}`.** Видаляє `styles/{style}` або весь `styles` на диску профілю `image` (`deleteDirectory`). Стилі після зміни розміру пресету інакше лишилися б старими. Нічого, крім `styles/`, не видаляє; назва стилю проходить ту саму перевірку, що й у маршруті, щоб `..` не вийшов за каталог.

**8. Медіатека.** `MediaController::row()` повертає в `preview` `image_style($this->storage->url($file), 'thumb')` для зображень; деталі (`url`) лишаються оригіналом. Колонка Preview у `Pages/Admin/Media/Index.tsx` стає `<a href={оригінал} target="_blank" rel="noopener noreferrer">` з `<img src={preview} className="cursor-pointer …">`; рядок отримує адресу оригіналу (`url`, `$this->storage->url($file)`) разом з `preview`. Документ лишається іконкою без посилання.

**9. `thumb` у списку записів і в `FileUpload`.** Дані файла для клієнта отримують поле `preview`: адреса стилю `thumb` для `image/*` (через `image_style()`), інакше `null`. Джерела: відповідь завантаження `FileController`, збірка відомих файлів `ContentNodeController::fileInfo` (поле `files`), `TermController`, `MenuItemController`, `SiteSettingsController`; комірка `image` у списку (`ContentNodeController::item`) віддає `Arr::only($file, ['url', 'name', 'preview'])`. Тип `ImageFile`/`UploadedFile` на клієнті отримує `preview: string | null`; клієнтські збірки значення (`TermForm`, `MenuItemForm`, `NodeFieldInput`) копіюють його з об'єкта файла. Компоненти показують `preview ?? url` (запасний варіант, коли `preview` немає, напр. у старих даних), а посилання завжди веде на `url` оригіналу. Комірка списку вже є посиланням, їй додається лише `cursor-pointer` і `thumb`; у `FileUpload` голий `<img>` обгортається в `<a target="_blank" rel="noopener noreferrer">`. Альтернатива — клієнт сам складає адресу `thumb` — відкинута: підпис і формат живуть на сервері.

## Risks / Trade-offs

- [Перший відвідувач чекає на генерацію] → мініатюри невеликі, `ImageResizer` швидкий; результат кешується на диску назавжди.
- [Паралельні перші запити генерують один файл двічі] → атомарний запис (тимчасове ім'я + перейменування), результат однаковий.
- [Каталог стилів росте, зайві довільні розміри] → підписані розміри обмежені тим, що задано в шаблонах; `image-styles:flush` очищає; межа сторони.
- [Підпис залежить від `APP_KEY`] → після зміни ключа старі довільні адреси дадуть 404 для ще не створених файлів; створені файли віддаються статично. Хелпер сформує нові адреси при наступному рендері.
- [Середовище, де front controller не перехоплює неіснуючі файли] → вимога стандартного налаштування Laravel (Apache `.htaccess`, nginx `try_files`) описується в `docs/image-styles.md`; без цього маршрут не спрацює.
- [Копія оригіналу в `styles/` для анімації дублює байти] → прийнято: простота й статична віддача важливіші за місце.
- [Розмиття дорожче за простий resize] → тло будується зі зменшеної копії; результат кешується; `thumb` створюється при завантаженні, а не під час перегляду.
- [Збільшення малого оригіналу дає м'яке зображення] → вибір власника; стиль не збільшує понад `max_dimension`, а завантаження оригіналів не змінюється.
- [Визначення прозорості дорожче за перевірку формату] → робиться раз на файл при створенні стилю; результат кешується.
- [WebP у режимі `webp` не відкриється в дуже старих браузерах] → режим `original` у налаштуванні; GIF не конвертується.
- [Створення `thumb` при завантаженні подовжує відповідь завантаження] → мініатюра невелика; збій не відхиляє завантаження.

## Migration Plan

Міграцій БД немає, наявні файли не змінюються. Розгортання: оновити код і `composer dump-autoload`, за потреби додати `FILES_STYLE_*` в `.env`. Відкат — прибрати код; каталоги `styles/` можна видалити вручну чи `image-styles:flush`.
