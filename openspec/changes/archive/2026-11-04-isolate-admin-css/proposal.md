# Proposal

## Why

Адмінка є ядром і має бути незалежною від теми: зміна шаблону теми (додавання Tailwind-класу) не повинна змінювати CSS адмінки. Зараз `resources/css/app.css` використовує автоматичне сканування Tailwind, яке охоплює весь проєкт, зокрема `themes/`. Через це класи, які існують лише в шаблонах теми (наприклад `aspect-video`, `max-w-prose`, `gap-x-6`), потрапляють в адмінську збірку. Тема при цьому має лишатися повністю вільною у стилізації.

## What Changes

- Адмінська таблиця стилів `resources/css/app.css` перестає сканувати весь проєкт: автоматичне сканування вимикається (`source(none)`), а сканування обмежується `resources/` і скомпільованими шаблонами `storage/framework/views`, плюс шаблони пагінації з `vendor`.
- Тема `default` і її таблиця стилів не змінюються: токени, шаблони та сканування `themes/*/views` лишаються як є.
- Додається вимога, що збірка адмінки не містить утиліт, які використовуються лише в шаблонах теми.

## Capabilities

### New Capabilities

Немає.

### Modified Capabilities

- `default-theme-styling`: додається вимога ізоляції стилів, щоб адмінська збірка не залежала від шаблонів теми. Вимога про те, що адмінка не отримує стилі теми, уже існує; нова вимога описує збірку.

## Impact

- Код: `resources/css/app.css` (одна директива сканування).
- Збірка: після `npm run build` адмінський CSS не містить утиліт, що є лише в `themes/`.
- Публічна тема: без змін.
- Документація: `docs/` — файл, який описує стилі адмінки та теми (`docs/admin-shell.md` або `docs/site-themes.md`), отримує короткий опис правила ізоляції. Конкретний файл уточнюється в tasks.
- Тести: PHP-тести не змінюються; перевірка через збірку та grep по `public/build`. E2E не запускаються, бо поведінка в браузері не змінюється.
