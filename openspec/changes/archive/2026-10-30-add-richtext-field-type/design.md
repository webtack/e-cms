# Design

## Context

Реєстр типів (`config/content.php` → `FieldType`) дозволяє додати тип без змін ядра; `image` і `file` уже використовують чужу таблицю через `table()`. `ContentValueWriter` спершу нормалізує значення (`''` → `null`, відкидає порожні елементи списку), потім валідує за `rules()` типу, потім зберігає `prepare()`. Форма поля не приймає `settings` для нефайлових типів (`settingsRules` → `prohibited`), тож `min`/`max` для `text` можна задати лише програмно. Віджет значення вибирається в одному місці — `NodeFieldInput.tsx`. Мотивація і межі — у `proposal.md`; вимоги — у `specs/`.

## Goals / Non-Goals

**Goals:**
- `richtext` як ще один тип реєстру з мінімальним втручанням в ядро.
- Безпека: єдиний авторитетний шар санітизації на сервері.
- Редактор вбудовується в наявну форму запису (рамка поля, підпис, помилки, множинні поля).

**Non-Goals:**
- Налаштування тулбара в `settings` (ключі `settings` для `richtext` лишаються забороненими, як у `text`).
- Вставка зображень, таблиць, код-блоків; медіатека; Markdown; колаборація.
- Рендеринг на сайті: тип віддає санітизований HTML.

## Decisions

**1. Формат: HTML у `content_values_text`.** Без нової таблиці й міграції: `RichTextType::table()` повертає `content_values_text`. Читання, множинність, переклади, фільтр `eq`/`contains` працюють як у `text`. Альтернатива — JSON-документ Tiptap/ProseMirror: точніший, але потребує рендерера в кожному клієнті, ламає `contains` і довжину. Відхилено.

**2. Санітизація: `symfony/html-sanitizer` (MIT) в окремому сервісі `App\Content\HtmlSanitizer`.** Allow-list задається в конфігу сервісу: теги `p br h2 h3 h4 strong em u s blockquote ul ol li a`, атрибут `href` для `a` зі схемами `http/https/mailto/tel`, `rel="noopener noreferrer nofollow"`, відносні посилання дозволені; `img` та інше викидається. Сервіс має `clean(string): string` і `text(string): string` (видимий текст). Чому не `ezyang/htmlpurifier`: важчий, потребує кеш-каталогу, старий API. Чому не санітизувати лише на клієнті: клієнт обходиться прямим запитом. Версію пакета підтвердить `composer require` (сумісність з Laravel 13 / Symfony); якщо несумісна, запасний варіант — `htmlpurifier`, поведінка за специфікацією не змінюється.

**3. Де санітизувати: у `prepare()`, а валідувати — у `rules()`.** `rules()` повертає `string` + замикання для довжини за `HtmlSanitizer::text()` (`min`/`max` із `settings`, якщо задано). `prepare()` повертає `clean()` — те, що йде в БД. Так при читанні завжди очищене значення, а ядро не знає про санітизацію. Альтернатива — прибрати лише на виводі: тоді в БД лежав би небезпечний HTML і кожен клієнт мав би санітизувати сам. Відхилено.

**4. Порожнє значення — невеликий загальний гачок.** `<p></p>` не `''`, тож `normalize()` у `ContentValueWriter` його б не очистив, а `required` пропустив би. Додаємо в `FieldType` метод `isBlank(mixed): bool` (у `AbstractFieldType` за замовчуванням `$value === null || $value === ''`, у `RichTextType` — немає видимого тексту й немає вкладених `img`/посилань не потрібно, бо `img` заборонено), і `ContentValueWriter::normalize` викликає його з типом поля (для списку — для кожного елемента). Альтернатива — лише клієнт шле `''` для порожнього редактора (`editor.isEmpty`): працює для адмінки, але не для API/seeder. Робимо обидва: гачок на сервері — гарантія, клієнтське `''` — зручність. Зміна ядра мінімальна й адитивна (поведінка інших типів не змінюється); вона описана в специфікації як виняток.

**5. Редактор: Tiptap 3 (`@tiptap/react`, `@tiptap/pm`, `@tiptap/starter-kit`; MIT).** `StarterKit` уже містить Link і Underline (підтверджено документацією Tiptap), тож додаткових пакетів немає. Компонент `RichTextEditor` у `Components/Admin/ContentNodes/`: `useEditor` з `StarterKit` (вимкнені `codeBlock`, `code`, `horizontalRule`, `strike` за потреби, заголовки h2–h4 відповідно до allow-list), `onUpdate` → `onChange(editor.isEmpty ? '' : editor.getHTML())`. Тулбар на наявних `Button`, іконки `lucide-react`; посилання — `Popover` з полем адреси. Стилі областей редагування — Tailwind (`prose`-подібні правила локально, без плагіна typography). Контрольований режим: `value` синхронізується з редактором лише коли відрізняється від `getHTML()`, щоб не губити курсор. `aria-label`/`id` та `aria-invalid` передаються на редагований елемент (`editorProps.attributes`), щоб `<label htmlFor>` і e2e працювали.
Альтернативи: Lexical (більше ручної роботи, HTML окремо), Plate/Slate (JSON), BlockNote/Editor.js (блочні, дублюють `block-types`), CKEditor/TinyMCE (ліцензії).

**6. Список записів: текст без тегів.** Для колонки `richtext` контролер перетворює значення на звичайний текст через `HtmlSanitizer::text()` і скорочує (наприклад, до 200 символів з «…»). Тип колонки лишається `text` (fallback `COLUMN_TYPES`), сортування недоступне, як для `text`.

**7. Тип у формі поля.** `richtext` з'являється у списку типів автоматично (з реєстру); слово «Rich text» потрапляє в `lang/*.json`. `settings` для нього заборонені, як для `text`.

## Risks / Trade-offs

- [XSS через обхід санітизації] → один авторитетний шар на сервері в `prepare()`, allow-list, тести на `script`, `onclick`, `javascript:`, `data:`, вкладені теги; значення читається вже очищеним.
- [Недовіра до даних, збережених до появи санітизатора] → у нового типу немає старих даних; зміна типу поля `text` на `richtext` — предмет окремої зміни про незмінність типу поля (див. її артефакти), цією зміною правило не чіпається.
- [Пошук `contains` збігається з тегами й сутностями (`&nbsp;`)] → прийнятне для першої ітерації, зафіксовано в документації; повнотекстовий індекс за видимим текстом — окремо.
- [Довжина за видимим текстом дорожча за `strlen`] → обчислюється лише коли задано `min`/`max`.
- [Зміна ядра (`isBlank`)] → адитивна, дефолт зберігає стару поведінку; покривається наявними тестами `ContentValueWriterTest` плюс новими.
- [Тип `@tiptap/*` і `typescript ^7`/`React 19`] → сумісність підтвердить `npm install` і `npm run build` (`tsc --noEmit`) на першому завданні; пакет ставиться з `--legacy-peer-deps` за `docs/e2e-testing.md`.
- [Курсор «стрибає» при контрольованому значенні] → синхронізація лише при розбіжності HTML, покрита e2e (введення кількох символів підряд).

## Migration Plan

Міграцій БД немає. Залежності: `composer require symfony/html-sanitizer` у контейнері `app`, `npm install --legacy-peer-deps @tiptap/react @tiptap/pm @tiptap/starter-kit` на хості, `npm run build`. Відкат: прибрати рядок `richtext` з `config/content.php` (поля цього типу перестануть бути придатними — перед відкатом їх видаляють) і залежності.
